## 3. Выводы

1. **На дефолтных настройках за неделю сделок нет** — winrate не определён. Это штатное
   поведение edge-guard: при 1 контракте комиссия круга (10 RUB) сопоставима с типичным
   отклонением спреда, и открывать позиции экономически невыгодно.
2. **При принудительном разрешении входов winrate по нетто 8–21 %** (по брутто — 46 %,
   доля выходов по TakeProfit — 67 %). Все конфигурации убыточны: комиссии в 7–11 раз
   превышают средний валовой результат сделки.
3. **Структурная причина:** в `SingleLegLeadLag` Z-score и `E_gross` считаются по спреду
   пары, а PnL формируется только ногой Leg1. На тестовой неделе спред возвращался
   преимущественно за счёт Leg2, поэтому 48 сделок с «тейк-профитом по спреду» дали лишь
   33 прибыльные по брутто. `DualLegHedged` ловит возврат спреда полностью, но платит
   вдвое больше комиссий — на этих данных тоже убыточен.
4. **Ограничение метода:** 1-мин свечи + детерминированный мостик `O→L→H→C` — грубое
   приближение L2. Окончательный вывод о winrate возможен только на реальном потоке
   (`--mode record` → `--mode backtest --source recordings`).
