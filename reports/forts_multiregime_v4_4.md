## 1. Устранение гэпов экспирации в `*_CONT` (§6 бага из v4.3)

### 1.1. Что сделано в `scripts/discover_forts_universe.py`

Склейка `{ASSET}_CONT` теперь **back-adjusted** (difference/Panama):

1. Для каждого семейства определяется активный контракт на каждый день (максимальный
   оборот) — как раньше.
2. На дне переключения считается **спред ролла** `ΔP = P_новый − P_старый`:
   - основной способ — **медиана разниц по общим минутам** дня ролла (обе серии ещё
     торгуются), поэтому в `ΔP` не попадает обычный ночной гэп;
   - fallback — `open нового` − `close старого` предыдущего дня (режим `edge`).
3. Вся более старая история сдвигается на накопленную сумму `ΔP`; в каждой свече
   пишется поле `adj` (на сколько пунктов её сдвинули).
4. Роллы складываются в `data_cache/forts_rolls.json`:
   `{TICKER: [{day, from, to, delta, mode}]}`.

Проверка: `28` серий с роллами, `207` переключений. Спред ролла и то, что осталось
на стыке (`close` предыдущего дня → `open` дня ролла) после правки:

| Серия | Ролл | ΔP (спред) | Стык `close→open` после правки |
|---|---|---|---|
| `SBRF_CONT` | 18.06.2026 `SRM6→SRU6` | −2 363 пт | обычный ночной гэп |
| `LKOH_CONT` | 17.09.2026 `LKU6→LKZ6` | −1 838 пт | −550 пт (рынок) |
| `Si_CONT` | 18.06.2026 `SiM6→SiU6` | +1 676 пт | +300 пт (рынок) |
| `Eu_CONT` | 18.06.2026 `EuM6→EuU6` | +1 450 пт | +391 пт (рынок) |
| `ROSN_CONT` | 16.09.2026 `RNU6→RNZ6` | +1 268 пт | 0.0 пт |
| `VTBR_CONT` | 19.06.2026 `VBM6→VBU6` | −575 пт | 0.0 пт |
| `GAZR_CONT` | 18.06.2026 `GZM6→GZU6` | +397 пт | 0.0 пт |

**Медиана |скачка| по всем 207 стыкам после правки — `0.02 пт`**; остались только

### 1.2. Разрез сделок на ролле (Rule A)

- `bot_a/backtest/rolls.py`: `load_rolls`, `roll_days`, `boundary_ms` — последний бар
  перед каждым переключением.
- `bot_a/backtest/walkforward.py::build_signals` и `swing_portfolio.run`: на баре-барьере
  позиция закрывается **по цене открытия** (`machine.force_close(bar, ROLL, price=bar.open)`,
  новая причина `BreakoutExitReason.ROLL`). Ролл **не считается стоп-аутом** — серия
  убытков и кулдаун не включаются.
- Комиссия и ГО считаются от **сырой** цены: `price − adj` (`Signal.adj`,
  `AccountPosition.adj`) — back-adjustment не искажает нотионал.

### 1.3. Чужие индексы исключены по умолчанию

`NASD_CONT` и `SPYF_CONT` убраны из универсума по умолчанию:
- `WalkForwardSettings.exclude_tickers = ("NASD_CONT", "SPYF_CONT")`;
- `scripts/multiregime_select.py` — исключены, включаются флагом `--allow-foreign`;
- `swingPortfolio.excludeTickers` в `appsettings.json`.

Эффект на Full: `+17 352 → +18 334 RUB` (и `PF 1.254 → 1.268`), ноябрьская корзина
теперь целиком из FX/товаров/акций РФ.

## 2. Анти-застой моментума (`stallBreakevenAtr` / `stallBars`)

Реализация в `bot_a/engine/breakout_fsm.py::_manage` (шаг 1d, перед обычным
breakeven-ратчетом):

```python
if position.mfe_points >= params.stall_breakeven_atr * atr:
    if position.mfe_points > position.stall_ref_mfe:
        position.stall_ref_mfe = position.mfe_points   # новый экстремум — счётчик сброшен
        position.stall_bars_seen = 0
    else:
        position.stall_bars_seen += 1
    if position.stall_bars_seen >= params.stall_bars:   # моментум умер
        stop = entry ± max(комиссия, stall_lock_atr * atr)  # фиксация прибыли
```

- Активируется **только если прибыль уже была** (`mfe >= stallBreakevenAtr`), то есть
  это не «мягкий безубыток на первом откате» (ошибка v3.2), а защита уже заработанного.
- `stallLockAtr = 0` → стоп ровно за комиссию; `1.0–1.5` → фиксирует `+1.0…+1.5 ATR`.
- Новая причина выхода `BreakoutExitReason.MOMENTUM_STALL`; позиция становится
  безрисковой (`breakeven_done = True`) → освобождает риск-слот (`freeSlotOnBreakeven`).

## 3. Лимит ГО на одну позицию (`maxPositionMarginPct`)

`swing_portfolio.SwingAccountSettings.max_position_margin_pct` (в бэктестере по умолчанию
`0` — выключено, чтобы не менять исторические прогоны), `WalkForwardSettings` и
`SwingRunnerSettings` — `35 %`:

```python
if settings.max_position_margin_pct > 0:
    per_position = util_cap * max_position_margin_pct / 100.0   # 37 500 ₽ × 35 % = 13 125 ₽
    quantity = min(quantity, int(per_position // margin_per_contract))
```

|---|---|---|---|---|---|---|---|---|
| без лимита | 318 | +4 856 | +13 478 | **+18 334** | 1.268 | 2.005 | 14.51 | 38 |
| `cap35` | 303 | +4 354 | +12 003 | +16 357 | **1.284** | **2.021** | **12.76** | 53 |
| `cap50` | 322 | +4 433 | +7 632 | +12 065 | 1.194 | 1.587 | 16.31 | 32 |

`cap35` — компромисс: `−1 977 RUB` Net, но `−1.75 п.п.` просадки и лучший `PF/Sharpe`.
`cap50` хуже по всем метрикам (не даёт набрать размер в лёгких парах, но и не спасает
от тяжёлых). Отказов по ГО становится больше (53): тяжёлые `USDRUBF`/`EURRUBF` чаще
получают `quantity = 0` — это и есть цель лимита, но в бэктесте такие отказы стоят
прибыли, потому что эти же контракты дают и лучшие сигналы.

## 5. Чего не удалось и почему

1. **Цель `+35–50 тыс. RUB` недостижима на текущем универсуме.** После выправления
   роллов видно, что треть прибыли v4.3 была артефактом. Реальные `+18.3 тыс. RUB`
   (`+89.8 %` годовых) при `DD 14.5 %` — это то, что даёт momentum-корзина из 30m-баров
   на `50 000 RUB` с комиссией Премиум.
2. **Сентябрь всё ещё убыточен** (`−4 298 RUB`) даже после правки. Это режимный провал:
   `ER_20` падает, пробои не отрабатывают. Без внутридневных движков (L2/OBI) его не
   вытащить.
3. **Анти-застой не спасает give-back.** Он режет и прибыль, и убыток; чистая разница
   отрицательна при любых порогах. Правильный инструмент против give-back — Chandelier-трейл
   (`trailTriggerAtr`), который уже включён.
4. **Лимит ГО на позицию** улучшает риск-профиль (`DD −1.75 п.п.`, `PF +0.016`), но не Net.
