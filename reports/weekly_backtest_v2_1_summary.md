Версии:

* **v1** — живой EWMA-Z, без profit-lock, статическая бета, `MaxHold` 180 с; внутриминутный мост строится независимо по каждой ноге (`phase_lock = false`).
* **v2** — `frozen_mu/sigma`, profit-lock, мейкерский тейк `max(1.6·fee, 0.70·dev)`, динамическая бета `cov(ΔV2,ΔV1)/var(ΔV1)` по тикам, `MaxHold` 600 с.
* **v2.1** — стационарная бета (`same_underlying` / `slow_ratio` + заморозка на входе), фазово-синхронный мост по ведущей ноге, калиброванный тейк `max(1.35·fee, 0.55·dev)`, мейкерский тайм-стоп 30 с, `MaxHold` 600 с.
* **v2.1-close** — то же, но `--synth-mode close`: только реальные закрытия 1-минутных баров (`EwmaWindow` 240).

Общие параметры матрицы: `Z_Entry` 2.8, `Z_Exit` 0.2, `Z_Stop` 4.2, `EwmaWindow` 2400 (ticks) / 240 (close).

## 7. Выводы

1. **v2.1 устраняет механические артефакты, но сама по себе не выводит стратегию в плюс.** Итог по 8 конфигурациям (Trader): v1 = −57.80 RUB, v2 = −460.63 RUB, **v2.1 (ticks) = −62.53 RUB**, v2.1 (close) = −63.83 RUB. Разница v2 → v2.1 почти целиком объясняется исчезновением фантомных сделок `CNYRUBF/CRZ6` (−439 RUB → 0…−28 RUB); на акциях результат v2.1 немного хуже v2 по net, потому что σ спреда стала честной (без β-джиттера), и стоп `Z_stop = 4.2` теперь срабатывает чаще (4–13 раз за неделю против 1–5 в v2).
2. **Лучший результат матрицы:** `VTBR/SBER`, `SingleLegLeadLag`, Premium, `Z_Entry 2.8`, `EWMA 1200` — **−0.71 RUB** за неделю (37 сделок, net-WR 43.2 %). Тот же пресет при `EWMA 2400` даёт −1.28 RUB (32 сделки), а v2 на этой паре при Trader — −0.69 RUB всего на 16 сделках (то есть v2 просто меньше торговал). Все результаты VTBR/SBER лежат в пределах 5–25 комиссий от нуля, что делает пару единственным кандидатом на дальнейшую донастройку.
3. **Горизонт удержания — главный оставшийся рычаг.** При `EWMA` 1200–2400 тиков (100–200 минут) половина сделок не успевает вернуться к среднему за `MaxHold` 600 с. Прогон v2.1+ (`MaxHold` 1800 с, `Z_stop` 6.0, Premium, ticks):
   * `VTBR/SBER` — **+0.12 RUB** (34 сделки, gross 58.8 %, net-WR 55.9 %, **3/5 прибыльных дней**) — первая положительная неделя за все версии;
   * `T/SBER` — −4.20 RUB, но средний gross **+0.044 RUB** и gross-WR **71.7 %**;
   * `CNYRUBF/CRZ6` — +8.67 RUB на 3 сделках (100 % net-WR), т.е. на календарном спреде сделки редки, но качественные.
4. **`DualLegHedged` на акциях экономически невозможен** при текущих тарифах: 4 стороны комиссии (0.28–0.45 RUB за круг) больше амплитуды спреда SBERP/T (±0.1–0.3 RUB). В v2.1 честная σ и edge-guard дают 0 сделок — это правильное поведение, а не баг. DualLeg остаётся осмысленным только для пар с широкой дисперсией (`IMOEXF/MMZ6`, `SVZ6/GDZ6`) и большим номиналом.
5. **`CNYRUBF/CRZ6` не пригодна для этой модели комиссии.** Круг стоит 6.14 RUB (Premium) / 9.83 RUB (Trader) при p99 спреда ≈ 10 RUB: достаточно одной неудачной сделки, чтобы съесть недельную прибыль. Пара остаётся в конфиге только как эталон «узкого календарного спреда».
6. **Тариф Premium обязателен.** Trader-комиссия 0.232 RUB (SBERP) и 0.217 RUB (T) при среднем gross 0.03–0.10 RUB делает большинство прибыльных по gross сделок убыточными по net; Premium снижает fee до 0.145/0.136 и поднимает net-WR с 31.8 % до **34.3 % (SBERP)** и с 38.2 % до **47.1 % (T/SBER)** при том же числе сделок.

## 8. Как воспроизвести

```powershell
# 1) недельный бэктест v2.1 по фазово-синхронному мосту
py -3 -m bot_a --mode backtest --source iss --preset VTBR_SBER `
    --z-entry 2.8 --z-exit 0.2 --ewma-window 1200 --tariff Premium `
    --topology SingleLegLeadLag --from 2026-10-18 --to 2026-10-25

# 2) то же без синтетики (только реальные 1-минутные закрытия)
py -3 -m bot_a --mode backtest --source iss --preset VTBR_SBER `
    --z-entry 2.8 --ewma-window 240 --synth-mode close --tariff Premium `
    --from 2026-10-18 --to 2026-10-25

# 3) grid-search по v2.1-параметрам
py -3 -m bot_a --mode optimize --source iss --preset VTBR_SBER `
    --tariff Premium --from 2026-10-18 --to 2026-10-25 --jobs 4

# 4) тесты (включая PhaseLockedBridge, StationaryBeta, maker-first TimeStop)

```

## 9. Ограничения этого сравнения

* Прогоны на 1-минутных свечах MOEX ISS: внутриминутная микроструктура (реальные OBI, очередь, спред) отсутствует — для окончательного решения нужен `--mode record` + `TickReplayBacktester` на реальном L2 (`bot_a/broker/tinkoff_rest_client.py`).
* Размер лота для акций взят из ISS `LOTSIZE` = 1 (SBERP/SBER/T/VTBR); при live-торговле `preflight` перезапишет метаданные значениями T-Invest.
* Результаты одной недели (5 торговых дней) статистически слабы: 14–37 сделок на конфигурацию; знак PnL меняется от сдвига `Z_stop`/`MaxHold` на один шаг сетки.
* Праздники MOEX и клиринговые окна моделируются только по расписанию; новостные гэпы не воспроизводятся.
